# B3 — Тест classifier на реальных данных

> Редактура 27.09.2026: это историческая исследовательская заметка. Численные сводки сохраняют исходную область применения; эта правка не является их общей повторной верификацией. Изменения вероятностей, физическое энергопотребление и предполагаемые механизмы различаются.

## Данные

30 моделей × 3 факта (H2O, 2+2, Canberra) из NVIDIA NIM. 130 samples (68 clean, 62 dirty) после фильтрации sentinel values (logprob = -9999).

## Ограничения данных

1. **Нет top-k logprobs** — API вернул только logprob выбранного токена, `top_logprobs: []`. Entropy вычислить невозможно. Использован NLL как 1D proxy.
2. **Очень короткие ответы** — медиана 4 токена (H2O→3 токена, 2+2→2-3 токена). Late fraction, roughness, spike ratio теряют смысл на 3-5 токенах.
3. **Низкий NLL ошибочных ответов** — dirty mean_nll (0.099) близок к clean mean_nll (0.076). Это наблюдение о вероятностях выбранных токенов, а не о намерениях модели.

## Результат

**LOO Accuracy: 46.2%.** Для вывода о качестве нужны явно заданный baseline и неопределённость оценки.

Feature distributions практически идентичны:

| Feature | Clean mean | Dirty mean | Separation |
|---|---|---|---|
| late_fraction | 0.402 | 0.419 | ~0 |
| roughness | 0.168 | 0.195 | ~0 |
| peak_nll | 0.364 | 0.430 | ~0 |
| mean_nll | 0.076 | 0.099 | ~0 |

## Интерпретация

**В этом тесте NLL-признаки выбранных токенов не дали убедительного разделения clean и dirty.** Возможные объяснения:

1. Entropy-сигналы из спринта (445×, p=3.8e-13) были вычислены из **полных top-k logprobs** (k=20), а не из одного значения.
2. Спринт использовал **длинные ответы** с teacher forcing, где entropy-профиль имеет структуру.
3. Низкий NLL выбранного токена совместим с фактически неверным ответом. Вероятность токена не является проверкой истинности.

## Условия следующей проверки classifier

1. **top-k logprobs** (k ≥ 5) — для вычисления настоящей entropy
2. **Длинные ответы** (≥ 20 токенов) — для профильных фичей (late fraction, roughness)
3. **Отдельный анализ коротких и длинных ошибочных ответов**, включая различия в NLL и длине.

## Вывод для paper

В проверенной конфигурации NLL-only proxy не показал полезного разделения условий. Этот тест не устанавливает причину результата и не доказывает, что top-k признаки необходимы или достаточны для успешного классификатора.
